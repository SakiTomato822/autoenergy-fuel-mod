# MCU 13/02 formatter 上游触发复核（2026-10-13）

## 结果

已闭合两个 formatter 之间的内部关系，但没有闭合从任务、注册表或 AP 请求到 formatter 的实际运行时调用关系。因此不能据此称 13/02 是周期上报、AP 请求响应或初始化导出。

- `0x44a518` 构造 `13/02` 项，状态与缓存分开读取；其 `0x44a5fe` 是 `b.w 0x449dc8`，所以该迭代路径会进入 `0x449dc8`。这只证明 formatter 间的内部调用，不证明谁调用 `0x44a518`。
- `0x449dc8` 也有按 index 的薄包装入口。`0x44a1c0` 将 `r0=20` 后跳到 `0x449dc8`；静态地址表在 ROM `0x48fa4c` 的 4 字节为 `c1 a1 44 00`，即 Thumb 指针 `0x0044a1c1`，指向该 index20 包装入口。这是具体的表项/注册候选证据；尚未找到消费这张表并实际 `blx` 该项的代码，故不把它写成已发生的 formatter 调用。
- `0x44a518` 的邻接边界支持它是独立函数：前一小函数在 `0x44a512` 返回，`0x44a514–0x44a516` 是字面池；formatter 从 `0x44a518` 开始，在 `0x44a602` 返回，下一入口在 `0x44a604`。没有依据把邻近代码误作其上游 fall-through。

## 主 13 的 6/8 分支

`0x44a6c8` 在 `0x44a702–0x44a70c` 按 mask `0x142` 接受 subcommand 1、6、8；队列项匹配后，subcommand 6/8 在 `0x44a772–0x44a784` 形成 `0x30000`/`0x20000` 参数并经 `0x42dc7e` 入队。队列分派 `0x45bc3c` 的 type 1 路径在队列项非空时跳到 `0x45a8e8`；该处理器对一类记录调用 `0x439984`。

`0x439984` 以 `0x48aaac` 为间接 handler 指针表，索引上限为 `0x334`。本次仅对这张有界表检查了 formatter 的 Thumb 指针 `0x44a519`、index 包装入口 `0x44a1c1` 和 `0x449dc9`；没有命中。因而这条 6/8 队列链目前没有到 formatter 的直接注册证据。间接 handler 内的进一步调用仍未闭合，不能据此断言整条链绝不可能到达 formatter。

另一个看似相关的状态维护路径 `0x43e1bc → 0x45b23a → 0x45ad0e → 0x4490c8` 进入队列 type 5/index20，消费者表项指向 `0x44e6d4`。该 handler 输出的是另一消息路径；现有证据没有把它接到 `13/02`，不将这条路径当作报告触发证据。

## 表与数据解释边界

物理 RX 描述表基址是 `0x20408bbc`；缓存/状态维护表则由 `*(0x20409804+0x218)` 指向 `0x20409a20`。两者不可互换。`0x44a518` 通过 `+0x1a8` 读取软件状态，并从缓存指针表 `0x2040aa78` 复制数据；`0x449dc8` 另外检查维护表 `+0x218` 的行字段，再独立读取状态和缓存。两端都没有在格式化时要求刚刚收到 CAN 帧。

`data-copy-map.json` 中列出的源区间为 `0x49a488–0x49eed0`、`0x49eed0–0x49fd2c`、空区间以及 `0x421000–0x421408`；没有覆盖 `0x44a518`、`0x449dc8` 或这些地址附近的复制代码证据。该映射不能排除未记录的运行时注册/间接调用。

## 未闭合关系与重查条件

缺失的关键关系是：**哪个实际任务、注册表消费者或上游回调调用 `0x44a518`，以及哪个消费者通过 `0x48fa4c` 一类表项调用 `0x44a1c0`/同组 wrapper。** 现有 6/8 队列证据只到 `0x439984` 的间接 handler 分派；现有 wrapper 表项只证明有静态指针，不证明运行时触发。当前也没有证据判定它由周期、AP 请求或初始化触发。

只有出现同版本静态材料中上述注册表的消费者/调用点，新的明确代码复制映射覆盖相应调用区，或既有运行记录保留了对应任务与回调地址时，才值得沿该缺口重查。无需重复读取全零缓存；单独的 13/02 数据也不能补出缺失的调用关系。
